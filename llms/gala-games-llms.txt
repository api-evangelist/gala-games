# Gala Games

> Gala (formerly Gala Games) is a Web3 gaming and entertainment company that operates GalaChain, a Hyperledger Fabric based Layer 1 built for games, music and film. Its public API surface is REST-first rather than RPC: chaincode contracts are exposed as OpenAPI-documented HTTP endpoints across eighteen mainnet channel/contract pairs, alongside a swap/wallet API, a block explorer and a DeFi backend.

This file was GENERATED by API Evangelist from the specifications and documentation Gala publishes. Gala does not serve an llms.txt of its own — https://gala.com/llms.txt returns HTTP 200 with the site's HTML shell (a single-page-app catch-all), not a document.

Note on agent access: every galachain.com and gala.com host serves a robots.txt declaring `Content-Signal: search=yes,ai-train=no,use=reference` and explicitly disallows Amazonbot, Applebot-Extended, Bytespider, CCBot, ClaudeBot, CloudflareBrowserRenderingCrawler, Google-Extended, GPTBot and meta-externalagent. Gala's published API specifications remain openly reachable; its marketing and documentation HTML does not welcome crawlers.

## The one thing to know first

Every write is a POST of a signed DTO, and every write carries a caller-supplied `uniqueKey`. GalaChain will not permit two transactions with the same `uniqueKey` to commit — a replay is rejected with `UniqueTransactionConflictError`. Retries are safe by construction, and a conflict means the original write already landed. There are no bearer tokens, no OAuth and no API keys for developers: writes are authenticated by a secp256k1 signature over the alphabetically-sorted, deterministically-stringified request body, verified against a public key registered on chain. Most reads need no credential at all.

## Agent access

- MCP: `npx -y @gala-chain/launchpad-mcp-server@latest`. **stdio only — there is no hosted MCP endpoint**, so an agent cannot reach Gala without a local install. Omit `PRIVATE_KEY` for read-only mode; supply it for trading, token creation and transfers. Covers the Launchpad product only; the four OpenAPI-documented APIs have no MCP tools.
- A2A agent card: none. `/.well-known/agent-card.json` and `/.well-known/agent.json` return 404 (or an HTML shell) on all nine Gala hosts probed.
- No `/.well-known/` document of any kind is served on any Gala host.

## Operational facts an agent should know

- Rate limit: GalaConnect enforces a global 20 requests per 10 seconds, returning 429 with a `Retry-After` header in whole seconds. No other Gala API publishes a limit, and no Gala API emits `X-RateLimit-*` or `RateLimit-*` headers.
- Never issue concurrent writes for the same wallet — serialization failures come back as HTTP 409.
- Fee quotes: append `/fee` to any GalaConnect route and POST the same body without `signature` or `uniqueKey`. Fees are denominated in GALA. The `/fee` routes are intentionally absent from the OpenAPI but exist for every route.
- Dry run: every gateway contract exposes a `DryRun` method that evaluates a DTO without committing. Use it before any signed write.
- Errors: no RFC 9457. Three envelopes — GalaChainResponse (`Status`, `Message`, `ErrorCode`, `ErrorKey`, `ErrorPayload`), GalaConnect application errors (`error`, `errorId`) and bubbled chain errors (`message`, `error.ErrorKey`, `errorId`). Quote `errorId` to support@gala.com.
- Token identity is a composite key `collection|category|type|additionalKey` (plus `instance` for a specific unit), e.g. `GALA|Unit|none|none`. `"none"` is a required literal value, not a null.
- Status page: none. There is no health dashboard for any Gala API; the only liveness signals are `GET /health` on the Block Explorer and `GET /api/v1/wallet/compat/health` on the DeFi backend.
- Deprecation: no policy, no `Sunset` or `Deprecation` header support. The former Gala Games Server API and Object API were retired without notice — `game-server-api.gala.games` is now NXDOMAIN and `creators.gala.com` 302s to the marketing site.
